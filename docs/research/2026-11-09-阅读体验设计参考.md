# 阅读体验设计参考

合并更新：2026-11-09；原始页面与源码核查：2026-11-07。本文合并原有前端体验和视觉复用两份报告，只保留设计依据、源码入口、许可和真实取舍。文中涉及 Docusaurus 的适配判断属于迁移前方案，不代表当前 Astro 已安装这些组件。

以下“本站复用方式”和优先级保留原调研时的建议，涉及 Docusaurus、React、CSS Modules、阅读设置和 One Dark Pro 的描述属于迁移前方案，不代表已实现。当前功能与写法见[阅读指南](../reading.md)，实现边界见[架构](../architecture.md)。框架、主题能力和个人站点关系由[选型报告](2026-11-09-博客框架与主题选型.md)维护，本篇按页面设计和源码复用查询。

## 设计约束

先选择完整文章页作为主参考，再核对头部、列宽、标题、目录、块间距和操作位置。颜色与字体接入语义变量；缺少的局部能力再选成熟库。上一轮把不同站点的功能转换为自有控件，却没有保留统一尺寸和层级，出现过多常驻工具栏；功能通过不代表视觉已获认可。

普通表格保持可横向比较的结构，内容量大时才增加排序等操作；代码使用已有成品工具栏；图片直接作为查看入口；Mermaid 默认显示图，失败时保留源文。设置、段落分享和预览只有在实际需要时增加，并维护键盘、焦点与窄屏行为。

## 调研依据与确定性

检查了五站首页、代表性文章、可获取的页面 HTML，以及能对应上的公开源码。还阅读了 Lowbee 和椒盐豆豉的装修记录。Niracler 的颜色和排版另外核对了作者提供的设计预览图与实际 token 文件。没有完成五站所有交互在真实浏览器中的逐项测试；不把源码中的能力写成已经验证的线上操作效果。

下文区分三类依据：**页面**表示抓取的线上结构或作者装修记录；**源码**表示仓库中存在实现；**建议**表示为本站拟定的适配方案。仓库主分支会变化，下面记录本次读取的快照。

## Tw93：学习正文排版与组件的克制

参考首页、代表性长文及个人站源码。它最有价值的地方是文章列表、正文、图片和目录的关系，适合技术博客保留个人风格，同时控制信息密度。[^front-tw93-home][^front-tw93-article]

| 内容         | 已核实的做法                                            | 本站的适配建议                                                   |
| ------------ | ------------------------------------------------------- | ---------------------------------------------------------------- |
| 字体气质     | 源码使用仓耳今楷一类楷体字体栈                          | 保留已选的 LXGW 与 JetBrains；借鉴字号、行高和留白，不重复换字体 |
| 阅读列宽     | SCSS 区分桌面、平板列宽及目录栏占用                     | 为正文、宽表、大图分别定义宽度，平板避免直接套桌面宽度           |
| 文章头部     | 标题、日期、分类等信息集中，正文直接开始                | 论文笔记采用标题、摘要、更新时间、阅读时长的固定层级             |
| 代码块       | 语言标签、复制反馈、窗口式顶栏                          | 扩展 Docusaurus 现有 CodeBlock；交通灯只作可选装饰               |
| 图片灯箱     | PhotoSwipe 资源按需加载，排除 emoji 与不应缩放的图      | 正文图和装饰图分开；点击大图时再加载复杂查看器                   |
| 目录密度     | JS 中少于 5 个有效标题不显示目录；超过 14 项时可退回 H2 | 长论文笔记默认显示主要层级，允许展开细节，不复制硬编码阈值       |
| 搜索弹层     | 搜索框、结果列表和键盘提示共同构成界面                  | 美化已有本地搜索，统一输入框、选中态、摘要和快捷键提示           |
| 正文后续阅读 | 模板把评论和继续阅读放在正文之后                        | 正文完成后提供同专题文章，避免正文中插入太多推荐                 |
| 小屏适配     | 字号、导航和列宽有独立断点                              | 单独检查横屏手机、平板竖屏和目录收起后的状态                     |

主要源码入口：`_layouts/post.html`、`_includes/search.html`、`js/index.js`、`_sass/_variables.scss`。代码复制与目录逻辑在同一 JS 文件中；PhotoSwipe 的延迟加载也可直接阅读。[^front-tw93-layout][^front-tw93-js][^front-tw93-search][^front-tw93-tokens]

建议借鉴它的正文秩序，暂不复制整套首页装饰、横幅标题动画和作者个人宣传模块。迁移后应由本站现有 One Dark Pro 颜色令牌控制，而不是引入另一套散落的颜色常量。

## Niracler：最值得学习的是设计系统

Niracler 的公开仓库叫 Bokushi。它有独立设计页面、`DESIGN.md`、颜色与排版 token 文件，以及浅深色设计预览图。对“系统管理配色”这一目标，它比单个酷炫组件更值得参考。[^front-niracler-design][^front-niracler-tokens]

### 视觉规范

| 方面       | 源码与设计预览体现的做法                                   | 本站建议                                                                     |
| ---------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 颜色角色   | page、surface、muted、主次文字、边框、强调和状态色分别命名 | 延续现有 `palette.css → theme.css → 组件` 的映射，补足图表、表格、提示块角色 |
| 明暗主题   | 浅色暖纸感，深色暖暗色，组件通过语义变量联动               | 保留 One Dark Pro；参考管理方式，暖纸色可作为以后独立方案                    |
| 字号层级   | 正文 17px，标题和说明文字使用不同级别                      | 统一正文、图注、元信息、代码、目录字号，避免每个组件自由定值                 |
| 阅读尺度   | 默认行高 1.75，正文 measure 为 68ch                        | 用作实验起点；中文配 LXGW、英文配等宽字体时需按实际字面宽度调试              |
| 间距       | 区分列表内紧密间距、普通块距和段落留白                     | 为段落、图注、代码、表格制定共同的纵向节奏                                   |
| 圆角与阴影 | 小控件、卡片、弹层分级                                     | 统一卡片和弹层，避免每一块都使用不同阴影                                     |
| 样式展示页 | 集中展示颜色、文字、卡片、按钮等                           | 增加本站 `/design` 或 `/playground`，作为维护入口                            |

源码中的“WCAG compliant”等注释是作者的声明，不能替代本站的对比度检查。移植颜色后，尤其要单独检查小号灰字、链接与代码注释。

### 内容与交互组件

| 组件         | 已核实能力                                          | 适配判断                                                     |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------ |
| 表格         | 柔和表头、斑马纹、悬停行、等宽数字、sticky 表头样式 | 高优先级；sticky 是否有效还取决于滚动容器与顶部导航偏移      |
| 手机表格     | JS 检查列数，超过 3 列的表可在窄屏变成逐行卡片      | 借鉴选项，不直接套用自动规则；论文对比表通常应保留横向布局   |
| 图片         | `figure/figcaption`、独立灯箱、前后切换、图片计数   | 高优先级；论文图需要原始比例和可读图注                       |
| 代码         | 语言顶栏、复制状态、Shiki 明暗主题                  | 借鉴视觉；本站先沿用 Prism，避免只为顶栏更换高亮引擎         |
| Mermaid      | CSS 变量定义节点、连线、标签、背景等颜色角色        | 高优先级；让 Mermaid 与 One Dark Pro 联动                    |
| 目录         | H2/H3 嵌套、编号、过滤脚注标题                      | 已有目录可继续增强，不再叠加第二套目录                       |
| 阅读进度     | 顶部细条按文章区域计算，而非把评论也算进正文        | 与已有返回顶部百分比共用计算源；是否再显示顶部条交给用户选择 |
| 站内文章预览 | 构建文章元数据映射，交给预览脚本显示标题、摘要等    | 中优先级；只针对站内链接做预览，适合作为“读前判断”           |
| 搜索         | 独立 SearchModal 组件和结果交互                     | 借鉴外观与键盘行为，保留已有中文本地索引                     |
| Spoiler      | 独立遮挡内容组件                                    | 可用于答案或推导提示，优先于复杂的新语法                     |
| 分享区       | 桌面侧栏和移动端浮动操作分开                        | 简化为复制链接、阅读设置即可，不照搬全部社交按钮             |

内容样式集中在 `src/styles/global.css`；响应式表格在 `src/scripts/blog-interactive.ts`；图片在 `Lightbox.astro` 和 `rehype-figure.mjs`；代码、站内预览各有独立脚本。[^front-niracler-prose][^front-niracler-interactive][^front-niracler-lightbox][^front-niracler-preview]

源码也有不宜直接照抄的部分：`rehype-figure.mjs` 遇到段落内有图片时会提取图片构造 figure，未同时保留段落中的其他文字。本站若做自动图注，转换条件应限定为“段落仅包含图片与空白”，并覆盖带链接图片、多图和图文混排的情况。[^front-niracler-figure]

## Lowbee 与 Koharu：视觉小块和复杂交互分开学习

### Lowbee 已公开说明的个人装修

Lowbee 的《初始之地 S2》按日期记录了实际修改；这比仅看上游主题功能列表更能判断作者做过哪些取舍。[^front-lowbee-custom]

| 内容       | 作者记录的实现或调整                                      | 本站建议                                                      |
| ---------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| 封面渐隐   | `PostItemCard.astro` 使用 `mask-image` 做图片到文本的过渡 | 用于少量精选卡片；普通论文条目保留清爽文本布局                |
| 引用贴纸   | 引用块增加来源后缀和贴纸式视觉                            | 可用于论文原句、核心结论；颜色使用本站 accent 的低透明度版本  |
| 图片说明   | 把图片 alt 显示在图片下方                                 | 设计上值得采用；实现时保留 alt 的替代文本职责，可另设 caption |
| 目录位置   | 2026-10-14 移除文章左侧标签栏并调整目录                   | 与本站停用 tag 的方向一致；阅读页优先给正文和目录空间         |
| 季节归档   | 最近一年按春夏秋冬组织文章推荐                            | 论文周报更适合“年份 → 月份/期号”；借鉴视觉分组，不强行季节化  |
| 更新时间   | 添加最后更新信息，曾加入“有更新”标记                      | 显示更新时间即可；更新排序应有明确数据来源                    |
| 首页信息区 | 最近 5 条嘟嘟、个人动态                                   | 可换成近期阅读/正在整理，但不应挤占论文入口                   |
| 图片编排   | 连续图片根据比例组合，作者修改过判定阈值                  | 论文多子图建议显式指定并排关系，不让照片比例规则决定语义      |
| 图鉴       | 每个物品一份 Markdown，用卡片展示                         | 可转化为工具/项目展示页，优先级低于论文阅读体验               |

值得注意的历史变化：作者在 2026-05-06 记录更新排序和更新徽标，2026-05-08 又暂停首页按更新时间排序，并移除 MDX 依赖。这些是其项目的经历，不足以推出“Docusaurus 也应移除 MDX”。对本站更有用的经验是控制页面复杂度、避免为了小组件重做内容链路。

### Koharu 上游的设置中心

读取的上游通过设置 registry、默认值文件和 store 管理选项。源码能力包括字体预设、字号、行高、正文宽度、两端对齐、阅读进度，以及动效强度等；部分节日和音乐选项有构建开关。[^front-koharu-settings][^front-koharu-defaults]

建议本站先提供以下精简设置，不复制全部主题控制面板：

| 设置     | 建议初始值或行为                               | 原因                         |
| -------- | ---------------------------------------------- | ---------------------------- |
| 明暗模式 | 保留当前默认暗色，允许切换浅色；可增加跟随系统 | 延续已确认偏好，兼顾访客     |
| 正文字号 | 建议提供 16、18、20px 或小范围步进             | 长文阅读中直接有用           |
| 行距     | 建议提供 1.7、1.8、1.9 三档                    | 减少无意义的精细调参         |
| 正文宽度 | 标准、宽屏两档                                 | 宽表和图可独立突破正文宽度   |
| 纯净阅读 | 收起非必要侧栏与装饰，保留退出入口             | 对长论文笔记价值高           |
| 动效     | 默认轻量，尊重系统减少动态效果设置             | 装饰效果不应影响滚动和定位   |
| 重置     | 一键恢复站点默认                               | 防止浏览者把页面调到难以阅读 |

当前中文 LXGW、英文 JetBrains 已经满足作者偏好，无需再要求访客安装字体，也不急于暴露本地字体选择器。设置保存在浏览器本地；首次渲染要尽早应用，避免进页面后字号和背景跳变。

### Koharu 上游的代码与图表查看器

| 模块                      | 源码核实到的能力                              | 迁移价值                                                   |
| ------------------------- | --------------------------------------------- | ---------------------------------------------------------- |
| `CodeBlockToolbar.tsx`    | 语言/标题、复制、全屏、符合条件的长代码折叠   | 高；沿用本站 CodeBlock 输出，在外层补工具栏                |
| `CodeBlockFullscreen.tsx` | 全屏代码、换行切换、复制、小屏关闭按钮        | 高；长训练脚本与配置更容易看                               |
| `MermaidToolbar.tsx`      | 图/源码切换、复制源码、全屏、拖动调整显示尺度 | 高；论文方法图和流程图直接受益                             |
| `DiagramFullscreen.tsx`   | 缩放、平移、适应窗口、键盘控制、导出入口      | 高；复杂交互可以收在查看器内部                             |
| `diagram-export.ts`       | 解析 CSS 变量，尝试导出 PNG，失败回退 SVG     | 中；先解决可读性，再做导出                                 |
| `ContentEnhancer.tsx`     | 单 React 根通过 portal 挂多个工具栏           | 可学习集中管理的思路，但 Docusaurus 更适合优先包裹已有组件 |

上游部分工具栏根据内容可见性挂载交互界面；这不等于整个工具栏脚本都按需下载。Mermaid 还区分等待、成功、错误和超时状态。导出逻辑特别处理了 SVG CSS 变量与 `foreignObject`，说明“加一个下载按钮”仍有跨浏览器细节。[^front-koharu-code][^front-koharu-mermaid][^front-koharu-diagram][^front-koharu-export]

本站无需把上游的 Astro 页面事件、Nanostores、Tailwind、图标系统和所有弹层整体搬入。建议使用现有 React 生命周期、CSS Modules、Docusaurus 路由与主题状态，重新实现选中的行为。

## 椒盐豆豉：内容发现和小组件的持续打磨

该站以 Hugo Book 为基础做了较重修改。其“装修小记之四、五”对样式和系列功能的说明很直接；适合按需求选小功能，不能当成现成 Docusaurus 主题。[^front-douchi-home][^front-douchi-four][^front-douchi-five]

| 内容         | 页面或作者记录中的做法                             | 本站建议                                                     |
| ------------ | -------------------------------------------------- | ------------------------------------------------------------ |
| 系列文章     | 文章带 series 参数，文末自动列出同系列并按日期排序 | 高优先级；利用已有 collections 数据，不恢复 tag              |
| 荧光笔       | 为 strong/b 添加低饱和渐变底色和圆角               | 做成可选 `<Mark>`；避免所有粗体都铺背景，尤其排除代码与公式  |
| 单篇精简目录 | 自建 compactToc 控制层级，解决目录过长             | 使用 Docusaurus 原有单页 TOC 层级参数，保留已有目录高亮      |
| 写作热力图   | 独立动态热力图页面，有专门实现教程                 | 可做笔记归档页的视觉入口；内容多了再做，点击应能进入当天文章 |
| 最近更新     | 新文章和更新过的旧文都有发现入口                   | 首页加一个小型“最近更新”，与论文笔记维护方式匹配             |
| 闲逛         | 随机发现文章入口                                   | 文章数量够多后做；只有几篇时价值有限                         |
| Now 页面     | 集中呈现近况与站点变化                             | 个人主页以后可加，当前不是阅读页核心                         |
| Reaction     | 评论系统之上增加轻量反应                           | 可选；涉及后端读写，不属于纯 CSS 美化                        |
| 单按钮音频   | 用紧凑播放按钮替代整条默认 audio 控件              | 有论文语音/播客内容再做，默认不要自动播放                    |
| 社交与书影音 | 长毛象、NeoDB 最近内容等展示区                     | 可借鉴卡片结构；本站优先展示近期阅读和研究项目               |

## 成品外观与基础能力的区别

“尽量不自己写”可以做到复用成熟组件的交互、样式和状态，但仍需要接入本站的数据与路由。应优先减少自行设计外观的工作，而不是只减少 TSX 行数。

| 方案                                                   | 是否自带成品外观                                | 当前项目的接入代价                                         | 推荐用途                                       |
| ------------------------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------- |
| Docusaurus 原生主题组件[^visual-docusaurus]            | 有，与 Infima 配套                              | 最低；通过 CSS、wrapper、必要的 swizzle 调整               | 目录、提示块、Tabs、代码、折叠等先保留原生能力 |
| 愧怍的 Docusaurus 源码                                 | 有，属于完整个人站设计                          | 中；处理 Tailwind、图标与内部接口                          | 最优先的同框架参考来源                         |
| Radix Themes[^visual-radix-demo][^visual-radix-source] | 有，提供按钮、Popover、Dialog、Table 等统一外观 | 中；导入成套 CSS，配置 Theme，并检查与 Infima 的样式作用域 | 确实缺少的设置面板、弹层或浮层                 |
| shadcn/ui[^visual-shadcn]                              | 有默认样式，以源码形式交付                      | 中；需要对应 Tailwind、颜色变量、工具函数和基础组件依赖    | 愿意维护复制进仓库的成品组件时使用             |
| Fumadocs UI                                            | 有                                              | 中到高；部分组件依赖内容处理、框架抽象和上下文             | 选定一整组文档式组件后评估，避免零散混搭       |
| Radix Primitives / 当前 Dialog                         | 无完整视觉方案                                  | 交互可复用，外观仍由我们承担                               | 保留基础行为；不能作为“已采用成熟设计”的依据   |
| PhotoSwipe / medium-zoom                               | 有各自的默认查看方式                            | 比自制查看器少；仍需适配正文图片与主题                     | 图片优先使用库提供的完整查看体验               |
| Panzoom / Mermaid                                      | 缩放行为库 / 图表引擎                           | 查看器控件仍要另找完整实现                                 | 不把它们当作现成的整套阅读组件                 |

shadcn 当前仓库包含不同基础组件版本，不能泛称全部只使用 Radix。已核对的 `new-york-v4/ui/hover-card.tsx` 带有圆角、边框、阴影、动画等实际样式类，因此它和裸 Radix HoverCard 的复用结果不同。Docusaurus 目前没有 Tailwind，接入时还需控制基础样式对 Infima 的影响。[^visual-shadcn-hover]

静态 Markdown 表格不建议直接套带排序、筛选、分页的 Data Table 示例。那类成品服务于交互式数据列表，会增加依赖与视觉负担；普通论文表格优先参考 AstroPaper 或 Starlight。

### 代码块优先考虑 Expressive Code

Expressive Code 是这批资料中最值得专门评估的成品内容渲染库。它提供 Markdown/MDX 的 Rehype 插件，编辑器和终端两类框架、标题、复制、文本标记和换行都有官方实现；Frames 默认随官方集成启用。[^visual-ec-repo][^visual-ec-frames]

可核对的源码包括 `packages/rehype-expressive-code/src/index.ts`、`packages/@expressive-code/plugin-frames/src/index.ts` 和 `styles.ts`。它对有文件名的代码和终端会话使用不同外观，不需要我们自己添加一条通用工具栏。

对本站有两个实际选择：近期采用愧怍的原生 Prism 代码块外观，依赖变化更少；希望直接采用 Expressive Code 的整套视觉和语法时，再做独立适配验证。后者要确认 Docusaurus 的 MDX 编译顺序、原生 CodeBlock 映射、Mermaid 代码围栏和服务端构建，尚未验证为“一行配置即可安装”。

## Off by One 图表案例

指定文章使用 Astro + MDX + React + TypeScript + SVG。`DayDetailEmbed` 是时间轴，`DaysGridEmbed` 是 100 天模拟网格，`FocusBlocksHeatmapEmbed` 是带阈值切换的热力图；组件通过 `client:load` 激活，代码使用 `useState`、`useMemo`、固定 seed 和独立模拟逻辑。作者没有用 ECharts、Chart.js、Recharts 或 D3 绘制这组图。[^astro-off-article][^astro-off-components]

作者公开了[嵌入指南](https://github.com/cduruk/offbyone/blob/09df1f3e4a0825b925ac88061cef623d0aee8301/src/components/poisson-interrupt/ASTRO_EMBEDDING_GUIDE.md)。可复用单位包括组件、模拟逻辑、UI 原语和 CSS，不是复制一个 `.tsx` 文件。图表代码继承 MIT；文章正文和图片另属作者内容。[^astro-off-license]

对论文周报，优先把交互放在解释论点的位置：切换 benchmark / 指标、方法图前后对照、一个参数的解释性模拟、附录或代码折叠。图表交互属于内容组件，主题只提供文章容器和样式约束。

## 验收与能力边界

固定演示页同时包含中英混排、长标题、普通与超宽表格、代码与自然语言 Prompt、长公式、横竖图片、图组、Mermaid 和提示块。明暗主题、390px 手机和桌面分别检查；弹层检查 Tab、Esc、焦点返回和路由切换清理。

若以后恢复段落分享，应校验原文，位置不匹配或文本不唯一时避免跳错；不得把临时位置当成永久引用编号。外部预览应明确数据来源，避免为了悬停摘要请求任意地址。导出 SVG / PNG 时需要处理字体、CSS 变量和 foreignObject，不能仅凭存在下载按钮认定跨浏览器有效。

原 Docusaurus 实现报告中的纯净模式、正文偏好、表格复制与全屏、段落分享、站内预览、Mermaid 下载不属于当前能力。重新引入时先核对现有库与内容需求，单独验证；过时组件路径和施工批次不继续作为维护入口。

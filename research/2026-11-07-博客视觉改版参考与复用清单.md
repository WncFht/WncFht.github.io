# 博客视觉改版参考与复用清单

调研日期：2026-11-07。目标：为当前 Docusaurus 网站找到可以完整模仿、携带样式复用的成熟实现。这里重新评估的是视觉来源与复用路线，不继续增加上一版的小组件。上一份[五站调研](./2026-11-07-博客前端与阅读体验调研.md)保留作为功能资料；其中“多站各取一部分、再自行统一设计”的建议由本文修正。

框架选型补充：若不以保留 Docusaurus 为前提，参见[长期博客框架选型与迁移调研](./2026-11-07-长期博客框架选型与迁移调研.md)。新报告按长期博客目标比较 Astro、Hugo、Next.js 等方案，优先推荐 Astro 加成熟主题；本文的同框架推荐适用于决定继续使用 Docusaurus 的情形。

## 1. 先看哪些成品

我的建议是：保留 Docusaurus 时，优先采用愧怍博客的文章页和控件组织；如果更喜欢此前明确认可的 Axi，就把 Axi 的文章页、列表和合集作为一整套视觉参考。两者应选一个作为主要来源。al-folio 用于比较论文展示，不同时引入另一整套文章样式。

| 优先级 | 直接看什么 | 最值得模仿的内容 | 接入当前网站的方式 |
| --- | --- | --- | --- |
| 1 | 愧怍的博客列表和任意技术文章[^kuizuo-demo] | Docusaurus 的博客结构、文章头部、代码块与目录 | 同框架源码适配，当前最实际 |
| 2 | Axi 本人博客与主题使用文档[^axi-demo] | 文章页整体布局、列表密度、专题入口、目录与进度 | Astro 模板和 Tailwind 样式转到 React；完整使用主题需迁移框架 |
| 3 | AstroPaper 首页、文章页和主题配色文章[^paper-demo] | 文字型列表、有限颜色角色、正文排版、轻量表格 | 参考 CSS 和完整页面比例；Astro 模板需转换 |
| 4 | Fumadocs 的 Notebook Layout、代码和图片示例[^fuma-demo] | 文档式长文、紧凑导航、目录轨迹、已经设计好的内容组件 | 局部适配；整站布局并非 Docusaurus 插件 |
| 5 | al-folio 的 Publications 和 Distill 示例[^al-demo] | 学术条目的信息层级、作者信息、论文式文章头部和公式区 | 学习完整信息结构；Jekyll 模板不能直接在 React 运行 |
| 6 | Starlight 的组件说明与示例[^star-demo] | 提示块、步骤、标签页、代码框、统一正文间距 | 内容组件样式参考；整套主题属于 Astro |

顺序按“适合当前网站并容易保留成品效果”排列，不代表这些项目的通用质量排名。Fumadocs、Starlight 是文档风格，Axi、AstroPaper 更像个人博客；这应在选择主参考时决定。

## 2. 上一版为什么需要重做视觉选择

上一版把参考站点的功能转换成了自己的组件，却没有保留一套完整设计的尺寸、层级和控件位置。表格、代码、Mermaid 都加常驻工具栏，阅读设置也长期占据页面角落，导致正文周围出现过多矩形控件。功能可用并不能证明视觉已经做好。

需要修正的工作方式如下。

| 上一版做法 | 成熟实现中可核实的替代 | 接下来应保留的约束 |
| --- | --- | --- |
| 每个内容块都增加一排文字按钮 | 愧怍把复制和换行放在代码右上角，默认隐藏，悬停或聚焦时显示[^kuizuo-code] | 操作入口不抢正文层级；触屏另行验证入口可发现性 |
| 每张表都有复制、展开工具栏 | AstroPaper 的 `ResponsiveTable` 只包裹可横向滚动、可键盘聚焦的容器[^paper-table] | 默认表格维持表格外观；只给确实需要的宽表增加操作 |
| Mermaid 同时强调源码和工具 | Vocs 的 Mermaid 实现默认只呈现图，渲染失败再显示错误[^vocs-mermaid] | 默认显示图；源码和导出是否保留需要单独取舍 |
| 从不同网站选功能，再自己设计组合 | Axi 的文章头、正文、目录、文末和返回顶部由页面布局共同组织[^axi-layout] | 先复刻一整页，再增加例外组件 |
| 引入 Radix Dialog 后认为已有成品样式 | Radix Themes 才提供成套样式；现有 Dialog 属于交互基础组件[^radix-demo] | 区分无样式基础库与有完整外观的组件库 |

这些是源码层面的对照，不表示候选网站的全部交互都已经在真实浏览器中逐项验收。

## 3. 最值得深入复用的项目

### 3.1 愧怍博客：保留 Docusaurus 的首选源码参考

仓库为 `kuizuo/blog`，MIT。读取的 `package.json` 使用 Docusaurus 3.10.1、React 19；当前仓库是 Docusaurus 3.10.2、React 19，因此它比 Astro 或 Next.js 模板更接近本站。源码还依赖 Tailwind、Iconify、Motion 等，不能把它当作仅复制一个 TSX 文件就完成的主题包。[^kuizuo-repo]

| 源码入口 | 核实到的实现 | 值得复用的部分 |
| --- | --- | --- |
| `src/theme/CodeBlock/Content/String.tsx` | 保留 Prism 高亮和 Docusaurus 的代码行处理；有标题时才显示标题栏；支持标题图标 | 文件名、语言、复制与换行的组织方式 |
| `src/theme/CodeBlock/Content/styles.module.css` | 按钮组绝对定位；按钮默认 `opacity: 0`；代码块悬停时变为 0.4，按钮悬停或聚焦时变为 1 | 直接参考尺寸、位置、边框与状态，取消本站额外的大工具栏 |
| `src/theme/BlogPostItem/Header/Info/index.tsx` | 使用原生文章上下文读取元信息、格式化日期与阅读时长 | 保留 Docusaurus 的内容模型，只复用展示层 |
| `src/theme/BlogPostItem/Header/Title/index.tsx` | 标题组件独立于摘要和元信息 | 整体移植头部层级，不单独给标题加装饰 |
| `src/theme/TOC/index.tsx` | 使用原生 `TOCItems` 和活动链接类，并加入 Motion 入场效果 | 原生目录结构和样式；入场动画可不选 |

源码入口见代码目录与博客组件目录。[^kuizuo-code][^kuizuo-blog][^kuizuo-toc]

推荐复用它的文章页控件，首页插画、社交图标、项目宣传无需一起搬。它使用的搜索服务也不要求跟随迁移，本站已有中文本地搜索可以继续提供数据。

同一 Docusaurus 次版本仍不代表内部接口完全一致。该源码使用 `theme-common/internal` 和 `CodeBlock/Content/String`，本站上一版改的是 `CodeBlock/Layout`。实际适配应对照当前框架提供的组件入口，保留视觉与样式来源，不能覆盖目录后假定兼容。

### 3.2 Axi Theme：应该模仿完整页面

仓库为 `Axi404/Axi-Theme`，Apache-2.0。此前选出的五个组件确实存在，但只移植行为没有保留它们依赖的布局和样式关系，是不够的。[^axi-repo]

| 源码入口 | 核实到的实现 | 应如何参考 |
| --- | --- | --- |
| `src/layouts/ContentLayout.astro` | 文章与右侧目录共用 flex 布局；侧栏 sticky；小屏隐藏侧栏；正文有 `min-w-0` | 连同正文列宽、目录占位、块距一起转换 |
| `src/layouts/BlogPost.astro` | Hero、TOC、正文、版权、相关文章、评论按 slot 组合 | 复刻文章页完整顺序，减少自行拼装 |
| `src/components/pages/PostPreview.astro` | 紧凑和详细两种展示；日期、摘要、阅读时长分层；封面是可选项 | Agent 和论文周报使用同一套列表语言，标签区按本站需求省略 |
| `src/components/pages/CollectionPreview.astro`、`CollectionHeader.astro` | 合集预览和专题头部有独立组件 | 连同专题页一起参考，避免只有两张孤立入口卡片 |
| `src/components/pages/TOC.astro`、`TOCHeading.astro` | 目录项高亮与每节进度共同呈现 | 复用视觉；活动章节数据优先沿用 Docusaurus 机制 |
| `src/components/pages/BackToTop.astro` | 返回顶部与文章阅读范围关联 | 只保留一个进度入口，不再叠加一套浮动工具 |
| `src/components/user/PublicationCard.astro` | 标题、作者、会议、状态、资源链接分层 | 可完整参考外观，但状态徽标数量应按真实内容取舍 |
| `src/components/advanced/MediumZoom.astro` | 正文图使用 medium-zoom，点击放大 | 图片无需常驻“放大”工具栏；查看器可以采用成熟库默认外观 |

布局、页面组件和用户组件都有明确源码入口。[^axi-layout][^axi-pages][^axi-user][^axi-zoom]

需适配的部分包括 Astro 的内容查询、图片、国际化路由和 Tailwind 工具类。可将模板转换为 React 并保留对应样式，也可以在决定更换框架后直接以主题为起点。后者更容易保留整站原貌，但文章路径、搜索、构建和部署都要重新评估，不能作为一次美化顺手完成。

这里也有不宜原样复制的细节：读取的 TOC 同时使用 `setInterval` 和滚动监听；移到 React 单页路由后，要处理监听清理与重复初始化。应复制经过选择的外观和必要实现，不照搬所有运行机制。

### 3.3 AstroPaper：适合文字和论文笔记的简洁路线

仓库为 `satnaing/astro-paper`，MIT。作者还提供 Figma 社区设计文件入口，可以在编码前核对原始布局，而不只凭网站印象自行画。这里确认了 README 中的设计文件链接，未逐页审查 Figma 文件。[^paper-repo][^paper-figma]

建议重点看这些源文件：

| 源码入口 | 可直接借鉴的内容 | 对本站的价值 |
| --- | --- | --- |
| `src/styles/theme.css` | 背景、文字、强调、弱化、边框等有限角色；分别定义明暗值 | One Dark Pro 可以映射到这些角色，避免每个组件单独选颜色 |
| `src/styles/global.css` | 正文容器统一为 `max-w-3xl`；交互元素有一致的键盘焦点 | 列宽与焦点样式有共同来源 |
| `src/styles/typography.css` | 正文内容的排版规则集中维护 | 标题、段落、列表、代码、表格一起移植与检查 |
| `src/components/ResponsiveTable.astro` | 横向滚动、焦点轮廓、最小宽度；提供简洁和斑马纹变体 | 可用原生 HTML/CSS 对等移植，不依赖复杂 React 状态 |

颜色与表格实现见对应源码。[^paper-style][^paper-table]

这条路线适合“首页和列表以文字为主，文章默认安静”。主题带有标签、归档等能力，不代表本站必须展示；可以保留文章列表的排版，继续暂时禁用标签。

### 3.4 Fumadocs：已经设计好的文档内容组件

仓库为 `fuma-nama/fumadocs`，MIT。它提供带外观的 UI 组件以及多种页面布局，当前 README 列出的支持范围包括 Next.js、使用 React 的 Astro，以及部分 Vite 框架。不能简单描述为“只能 Next.js”，也不能据此认为整个包可直接用于 Docusaurus。[^fuma-repo]

| 源码入口 | 成熟设计与行为 | 迁移边界 |
| --- | --- | --- |
| `packages/radix-ui/src/components/codeblock.tsx` | 代码框、标题、图标和复制入口 | 配套 MDX/Rehype Code 结构、样式与依赖需要一起处理 |
| `packages/radix-ui/src/components/image-zoom.tsx`、`image-zoom.css` | 图片直接点击缩放；Lightbox 支持组内切换和 caption | 使用框架图片抽象、翻译上下文和 React 图片缩放库，不能只复制文件 |
| `packages/radix-ui/src/components/toc/clerk.tsx` | 沿目录层级绘制细轨迹；活动区间使用 SVG 裁切呈现 | 适合参考目录外观；行为依赖 Fumadocs TOC 上下文 |
| `packages/radix-ui/src/components/callout.tsx` | 统一提示块的图标、内容与边界 | 可以把同类视觉映射到 Docusaurus 原生 admonition |
| `packages/radix-ui/src/layouts/notebook` | Notebook 页面布局的完整实现 | 依赖路由、页面树和 Provider；作为完整页面参考更合适 |

当前快照的 UI 源码实际位于 `packages/radix-ui` 和 `packages/base-ui`，不使用旧资料中常见的 `packages/ui` 路径。代码块文档说明其与 Rehype Code 配套；图片文档明确给出 MDX `img` 映射和 Lightbox 用法。[^fuma-code][^fuma-image][^fuma-toc]

最值得学的是目录细线、紧凑操作与内容组件的统一密度。对于现有 Docusaurus，我建议先复用选定的视觉结构，评估所需上下文后再决定是否引入组件包，不为一个按钮引入整个布局系统。

### 3.5 al-folio：学术展示与论文式文章的参考

仓库为 `alshedivat/al-folio`，MIT，运行于 Jekyll。已经检查作者发布的 Publications 和 Distill 预览图。Publications 使用年份分组、缩略图、标题、作者、会议和资源入口；Distill 示例将标题、摘要、作者机构、发布日期与正文分区呈现，目录与公式各有独立空间。[^al-repo][^al-preview]

可以参考这种信息层级；预览图中的大标题尺寸、紫色强调和留白无需照单全收。论文笔记需要优先展示“论文标题、来源、笔记摘要”，自己的正式 Publications 页面再展示作者和发表状态，避免把所有笔记都包装成自己的成果。

当前 README 将项目描述为轻量起始仓库，运行能力由独立版本的插件 gem 提供。`Gemfile` 包含 `al_folio_core`、`al_folio_distill` 等。因此网上旧教程中的 `_includes/bib.liquid` 等路径不能未经检查就列为当前仓库可复制文件；这里提供可确认的预览目录、文章配置与插件依赖入口。[^al-gemfile]

### 3.6 Starlight：内容组件应成套学习

仓库为 `withastro/starlight`，MIT，是 Astro 文档主题。当前源码的用户组件在 `packages/starlight/src/user-components`，包括 `Aside.astro`、`Tabs.astro`、`Card.astro`、`CardGrid.astro` 和 `Steps.astro`。正文 CSS 集中在 `src/style/markdown.css`，提示块另有 `asides.css`。[^star-repo][^star-components][^star-style]

值得模仿的细节包括：正文块间距由共享变量控制；标题前的间距与普通块不同；列表项使用较紧密的间距；提示块标题和内容分开；内容 CSS 有明确作用域和排除 UI 组件的机制。这比给每个 Markdown 元素随手设置 margin 更容易保持一致。

代码方面，其包依赖中已经包含 `astro-expressive-code`。如果采用 Starlight，成熟代码框是主题集成的一部分；如果继续 Docusaurus，则应单独评估 Expressive Code 的 Rehype 集成，不能安装 `astro-expressive-code` 来接管本站。[^star-package]

## 4. 其他候选与取舍

| 项目 | 已核实的类型与许可 | 可以学什么 | 对本站的判断 |
| --- | --- | --- | --- |
| Nextra[^nextra] | Next.js 文档方案；MIT | 代码行号、行/字符高亮、提示块、目录；代码 CSS 有独立源码 | 作为文档风格对照；无需为了这些局部样式迁移到 Next.js |
| Vocs[^vocs] | 独立文档方案；MIT；当前源码包含 React、Vite/Waku 相关接口 | 默认内容呈现简洁，Mermaid 默认无大工具栏 | 参考组件取舍；不按旧版技术介绍假定可直接接入 Docusaurus |
| Fuwari[^fuwari] | Astro 博客主题；MIT | 圆角卡片、元信息、封面与主题强调色的统一 | 喜欢图文型个人博客时可选；不推荐把大横幅作为论文站默认布局 |
| Astro Koharu[^koharu] | Astro 博客主题；AGPL-3.0 | 设置面板、图表查看等较完整交互 | 作为能力和完整界面对照；不再只抽出按钮自己重画 |
| Bokushi / Niracler[^bokushi] | Astro 个人博客；CC BY-NC-SA 4.0 | 设计令牌、样式展示、正文组件一致性 | 适合学习设计管理；复制代码和样式前需按其许可条件处理 |
| Tw93 个人站[^tw93] | Jekyll；MIT | 正文、元信息、图片查看与文章列表的克制 | 保留为文字型博客参考，具体源码已在五站调研记录 |
| 潮流周刊[^weekly] | Astro；`package.json` 声明 MIT，先前核查未见独立根许可证 | 周报首页、封面列表、往期导航 | 学习周报整页；文章与照片不随主题复制 |
| 椒盐豆豉[^douchi] | Hugo Book 深度修改；作者说明个人仓库已私有 | 系列导航、近期更新、局部强调 | 可读装修记录，不能承诺有完整个人主题可搬 |

Fuwari 作者发布的预览展示了明显的大横幅、圆角卡片和图文侧栏；这种视觉有完整性，但与简洁论文阅读是不同方向。[^fuwari-preview]

这些项目不能按“都开源所以随便抄”处理。MIT 和 Apache-2.0 项目也应保留要求的许可与声明；AGPL 与 CC BY-NC-SA 有不同条件。代码许可还不自动覆盖照片、插画、文章和商标。这里的许可证记录用于选择复用来源；实际取用时按具体文件核对。

## 5. 成品组件与基础库的区别

“尽量不自己写”可以做到复用成熟组件的交互、样式和状态，但仍需要接入本站的数据与路由。应优先减少自行设计外观的工作，而不是只减少 TSX 行数。

| 方案 | 是否自带成品外观 | 当前项目的接入代价 | 推荐用途 |
| --- | --- | --- | --- |
| Docusaurus 原生主题组件[^docusaurus] | 有，与 Infima 配套 | 最低；通过 CSS、wrapper、必要的 swizzle 调整 | 目录、提示块、Tabs、代码、折叠等先保留原生能力 |
| 愧怍的 Docusaurus 源码 | 有，属于完整个人站设计 | 中；处理 Tailwind、图标与内部接口 | 最优先的同框架参考来源 |
| Radix Themes[^radix-demo][^radix-source] | 有，提供按钮、Popover、Dialog、Table 等统一外观 | 中；导入成套 CSS，配置 Theme，并检查与 Infima 的样式作用域 | 确实缺少的设置面板、弹层或浮层 |
| shadcn/ui[^shadcn] | 有默认样式，以源码形式交付 | 中；需要对应 Tailwind、颜色变量、工具函数和基础组件依赖 | 愿意维护复制进仓库的成品组件时使用 |
| Fumadocs UI | 有 | 中到高；部分组件依赖内容处理、框架抽象和上下文 | 选定一整组文档式组件后评估，避免零散混搭 |
| Radix Primitives / 当前 Dialog | 无完整视觉方案 | 交互可复用，外观仍由我们承担 | 保留基础行为；不能作为“已采用成熟设计”的依据 |
| PhotoSwipe / medium-zoom | 有各自的默认查看方式 | 比自制查看器少；仍需适配正文图片与主题 | 图片优先使用库提供的完整查看体验 |
| Panzoom / Mermaid | 缩放行为库 / 图表引擎 | 查看器控件仍要另找完整实现 | 不把它们当作现成的整套阅读组件 |

shadcn 当前仓库包含不同基础组件版本，不能泛称全部只使用 Radix。已核对的 `new-york-v4/ui/hover-card.tsx` 带有圆角、边框、阴影、动画等实际样式类，因此它和裸 Radix HoverCard 的复用结果不同。Docusaurus 目前没有 Tailwind，接入时还需控制基础样式对 Infima 的影响。[^shadcn-hover]

静态 Markdown 表格不建议直接套带排序、筛选、分页的 Data Table 示例。那类成品服务于交互式数据列表，会增加依赖与视觉负担；普通论文表格优先参考 AstroPaper 或 Starlight。

### 5.1 代码块优先考虑 Expressive Code

Expressive Code 是这批资料中最值得专门评估的成品内容渲染库。它提供 Markdown/MDX 的 Rehype 插件，编辑器和终端两类框架、标题、复制、文本标记和换行都有官方实现；Frames 默认随官方集成启用。[^ec-repo][^ec-frames]

可核对的源码包括 `packages/rehype-expressive-code/src/index.ts`、`packages/@expressive-code/plugin-frames/src/index.ts` 和 `styles.ts`。它对有文件名的代码和终端会话使用不同外观，不需要我们自己添加一条通用工具栏。

对本站有两个实际选择：近期采用愧怍的原生 Prism 代码块外观，依赖变化更少；希望直接采用 Expressive Code 的整套视觉和语法时，再做独立适配验证。后者要确认 Docusaurus 的 MDX 编译顺序、原生 CodeBlock 映射、Mermaid 代码围栏和服务端构建，尚未验证为“一行配置即可安装”。

## 6. 原来的十项应分别参考什么

这张表用于替换上一版“实现一遍全部功能”的推进方式。先确定页面主参考，再让局部组件服从它的尺寸、色彩和密度；不是把表中所有项目的默认皮肤同时装进网站。

| 项目 | 首选参考 | 可以复用或模仿的内容 | 应减少的自行设计 |
| --- | --- | --- | --- |
| 1. 正文与主题 | 愧怍整篇文章；或 Axi 整篇文章 | 头部、列宽、目录位置、标题层级、块间距作为整体 | 自由组合多站的字号和卡片样式 |
| 2. 表格 | AstroPaper `ResponsiveTable`；Starlight 正文 CSS | 原生表结构、滚动、表头、边框、焦点 | 每张表的常驻工具栏 |
| 3. 长文定位与阅读设置 | Axi 完整目录；Fumadocs 目录轨迹 | 侧栏位置、活动状态、手机入口；设置使用选定的成品 Popover | 多个常驻浮动面板与重复进度 |
| 4. 图片与图注 | Axi 的 medium-zoom；Fumadocs ImageZoom；现有 PhotoSwipe 默认皮肤 | 图片本身作为入口，查看器沿用成熟交互 | 另造一套图片按钮和弹层 |
| 5. 代码块 | 愧怍；需要成品渲染时用 Expressive Code | 标题、复制、换行、编辑器/终端框 | 统一大工具栏与默认全功能按钮 |
| 6. Mermaid | Vocs 的默认图呈现；复杂查看可参考 Koharu 全套界面 | 默认安静展示，复杂功能放入查看状态 | 图上、图下各一排操作 |
| 7. 专题与周报 | Axi 的完整合集页；潮流周刊完整往期页 | 列表密度、期号、摘要、年份与导航 | 每个专题各自重新设计卡片 |
| 8. 提示与折叠 | Docusaurus 原生；Starlight Aside | 有限的语义色、图标、标题和内容间距 | 把所有引用、提示、折叠做成同一种厚卡片 |
| 9. 搜索 | 原索引配套 UI；或选定主参考的搜索外观 | 输入框、结果层级、活动项与键盘提示 | 用一个普通自制 Dialog 拼出所有细节 |
| 10. 预览与段落分享 | 需要时使用 Radix Themes HoverCard / shadcn HoverCard | 成品浮层的定位、动画、阴影；本站只接内容 | 自制浮层边界、定位与多套装饰 |

第 10 项不应成为视觉改版前置条件。字体、列宽、列表、正文块与目录没有跟随主参考之前，增加预览和分享不会解决“看起来不协调”的问题。

## 7. 三条可选择的完整路线

| 路线 | 页面主参考 | 成品复用策略 | 适用判断 |
| --- | --- | --- | --- |
| A. 保留 Docusaurus，采用成熟同框架布局 | 愧怍 | 复用文章、元信息、代码与目录的源结构和样式；保持本站内容、字体和主题色 | 我优先推荐，框架差异最少 |
| B. 保留 Docusaurus，忠实转换 Axi 外观 | Axi Theme | 先转换文章页、列表页、合集页的结构和样式，再接 Docusaurus 数据 | 最符合你此前对 Axi 的明确偏好，但转换工作多于 A |
| C. 以现成主题重建 | Axi / AstroPaper；文档型网站可用 Starlight | 尽量用主题原有页面和组件，仅改内容与少量品牌设置 | 愿意承担框架迁移时，最容易接近原主题成品 |

不建议为了获得 Fumadocs 的某一个代码框或 al-folio 的论文条目，就迁移整站。也不建议此时先引入一套新的大型 UI 体系，再自行设计所有页面。

One Dark Pro 可以继续保留，但先作为颜色输入。正文、面板、边框、弱化文字和强调色应映射到选定主参考的语义角色；代码高亮使用原配色。颜色、字体可以替换，页面比例、层级和操作位置应尽量忠于主参考，否则仍会变成另一轮自由发挥。

## 8. 后续实施与验收标准

下一阶段的最小交付应是一张忠实参考的文章页，包含标题、摘要、元信息、目录、公式、普通表格、宽表、代码、图片、Mermaid 和提示块。验收以参考页面并排比较为主：正文占比、头部高度、目录占位、控件位置、间距和信息密度都要可对照。

文章页确认后，才扩展到博客列表、Agent 专题、论文周报专题和 Publications。需要的小组件优先沿用同一主参考；主参考没有的组件，才从已经选定的成品库补齐。

复用记录应具体到上游仓库、提交、源文件、许可证、保留的样式、转换内容和主动省略的部分。更新上游时可以比较对应文件，避免只在文档里写一句“灵感来自某站”。

本文只新增研究材料，没有修改站点界面、安装依赖或迁移框架。MOPD 论文文件继续保留在本地，不纳入研究材料的提交范围。

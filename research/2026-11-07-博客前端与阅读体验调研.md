# 博客前端与阅读体验调研

调研日期：2026-11-07。对象：Tw93、Niracler、Lowbee、椒盐豆豉、潮流周刊。适配目标：当前仓库的 Docusaurus 论文笔记、技术博客、Agent 与论文周报专题。

## 1. 建议采用的方向

建议保留现有 Docusaurus，把视觉和交互分成四层：Niracler 的设计规范、Tw93 的长文排版、潮流周刊的周报展示、Koharu 的内容工具栏。椒盐豆豉适合参考系列导航、文章发现和轻量强调样式。五个站点的框架不同，可以迁移的是设计和组件行为，整套主题不能作为 Docusaurus 插件直接安装。

优先建设一张长期保留的“排版实验页”：同一页放中英混排、论文表格、代码、Mermaid、公式、横竖图片、提示块和折叠块。以后换配色、改字体、调间距，都在这一页比较。这比持续往首页增加小组件更能控制整站质量。

| 参考站点 | 最值得学习的部分 | 迁移到本站的定位 |
| --- | --- | --- |
| Tw93 | 正文节奏、克制的元信息、图片查看、按内容复杂度控制目录 | 技术长文的排版参考 |
| Niracler | 设计令牌、组件展示页、表格、图片、搜索与交互的一致性 | 整站设计系统的主要参考 |
| Lowbee | 封面渐隐、引用贴纸、图片说明、季节归档、文章页取舍 | 卡片和内容块的局部美化 |
| Koharu 上游主题 | 阅读设置、代码全屏、Mermaid 查看器、统一工具栏 | 复杂交互的实现参考，区别于 Lowbee 已部署功能 |
| 椒盐豆豉 | 系列文章、荧光笔强调、热力图、最近更新与闲逛入口 | 专题内导航与内容发现 |
| 潮流周刊 | 周报卡片、往期导航、纯净阅读、段落分享、图片加载策略 | 论文周报专题的参考 |

这里的取舍是面向当前网站的设计建议；各站点事实依据见后文对应来源。

## 2. 调研依据与确定性

检查了五站首页、代表性文章、可获取的页面 HTML，以及能对应上的公开源码。还阅读了 Lowbee 和椒盐豆豉的装修记录。Niracler 的颜色和排版另外核对了作者提供的设计预览图与实际 token 文件。没有完成五站所有交互在真实浏览器中的逐项测试；不把源码中的能力写成已经验证的线上操作效果。

下文区分三类依据：**页面**表示抓取的线上结构或作者装修记录；**源码**表示仓库中存在实现；**建议**表示为本站拟定的适配方案。仓库主分支会变化，下面记录本次读取的快照。

| 项目 | 核实到的技术来源 | 源码快照与复用边界 |
| --- | --- | --- |
| Tw93 | Jekyll，公开个人站仓库 | `tw93/tw93.github.io@06b9672`；根目录 `License` 为 MIT[^tw93-repo] |
| Niracler | Astro，公开仓库 Bokushi | `niracler/bokushi@c2f669a`；根目录声明 CC BY-NC-SA 4.0，不能按 MIT 代码库处理[^niracler-repo] |
| Lowbee | 线上使用 Astro；作者基于 Astro Koharu 装修 | 找到上游 `cosZone/astro-koharu@329ce55`，未确认个人魔改的完整公开仓库；上游为 AGPL-3.0[^koharu-repo] |
| 椒盐豆豉 | Hugo，页脚明确标注 Book w/ heavy mod | 作者装修文说明个人站仓库已转为私有；公开教程可读，未确认可整体复用的个人站公开仓库[^douchi-five] |
| 潮流周刊 | Astro，公开仓库 | `tw93/weekly@542800e`；`package.json` 声明 MIT，本次未见独立根目录 LICENSE；文章和图片需单独区分[^weekly-repo] |

Lowbee 线上页面标注的 Astro 为 5.18.0，而读取的 Koharu 主分支包版本为 7.7.4、Astro 为 7.1.3。后文的设置中心、图表导出等按“上游源码能力”记录，不能据此断言 Lowbee 当下全部启用。复用时应逐文件确认许可、依赖与署名要求；外观和行为也可以自行实现。

## 3. Tw93：学习正文排版与组件的克制

参考首页、代表性长文及个人站源码。它最有价值的地方是文章列表、正文、图片和目录的关系，适合技术博客保留个人风格，同时控制信息密度。[^tw93-home][^tw93-article]

| 内容 | 已核实的做法 | 本站的适配建议 |
| --- | --- | --- |
| 字体气质 | 源码使用仓耳今楷一类楷体字体栈 | 保留已选的 LXGW 与 JetBrains；借鉴字号、行高和留白，不重复换字体 |
| 阅读列宽 | SCSS 区分桌面、平板列宽及目录栏占用 | 为正文、宽表、大图分别定义宽度，平板避免直接套桌面宽度 |
| 文章头部 | 标题、日期、分类等信息集中，正文直接开始 | 论文笔记采用标题、摘要、更新时间、阅读时长的固定层级 |
| 代码块 | 语言标签、复制反馈、窗口式顶栏 | 扩展 Docusaurus 现有 CodeBlock；交通灯只作可选装饰 |
| 图片灯箱 | PhotoSwipe 资源按需加载，排除 emoji 与不应缩放的图 | 正文图和装饰图分开；点击大图时再加载复杂查看器 |
| 目录密度 | JS 中少于 5 个有效标题不显示目录；超过 14 项时可退回 H2 | 长论文笔记默认显示主要层级，允许展开细节，不复制硬编码阈值 |
| 搜索弹层 | 搜索框、结果列表和键盘提示共同构成界面 | 美化已有本地搜索，统一输入框、选中态、摘要和快捷键提示 |
| 正文后续阅读 | 模板把评论和继续阅读放在正文之后 | 正文完成后提供同专题文章，避免正文中插入太多推荐 |
| 小屏适配 | 字号、导航和列宽有独立断点 | 单独检查横屏手机、平板竖屏和目录收起后的状态 |

主要源码入口：`_layouts/post.html`、`_includes/search.html`、`js/index.js`、`_sass/_variables.scss`。代码复制与目录逻辑在同一 JS 文件中；PhotoSwipe 的延迟加载也可直接阅读。[^tw93-layout][^tw93-js][^tw93-search][^tw93-tokens]

建议借鉴它的正文秩序，暂不复制整套首页装饰、横幅标题动画和作者个人宣传模块。迁移后应由本站现有 One Dark Pro 颜色令牌控制，而不是引入另一套散落的颜色常量。

## 4. Niracler：最值得学习的是设计系统

Niracler 的公开仓库叫 Bokushi。它有独立设计页面、`DESIGN.md`、颜色与排版 token 文件，以及浅深色设计预览图。对“系统管理配色”这一目标，它比单个酷炫组件更值得参考。[^niracler-design][^niracler-tokens]

### 4.1 视觉规范

| 方面 | 源码与设计预览体现的做法 | 本站建议 |
| --- | --- | --- |
| 颜色角色 | page、surface、muted、主次文字、边框、强调和状态色分别命名 | 延续现有 `palette.css → theme.css → 组件` 的映射，补足图表、表格、提示块角色 |
| 明暗主题 | 浅色暖纸感，深色暖暗色，组件通过语义变量联动 | 保留 One Dark Pro；参考管理方式，暖纸色可作为以后独立方案 |
| 字号层级 | 正文 17px，标题和说明文字使用不同级别 | 统一正文、图注、元信息、代码、目录字号，避免每个组件自由定值 |
| 阅读尺度 | 默认行高 1.75，正文 measure 为 68ch | 用作实验起点；中文配 LXGW、英文配等宽字体时需按实际字面宽度调试 |
| 间距 | 区分列表内紧密间距、普通块距和段落留白 | 为段落、图注、代码、表格制定共同的纵向节奏 |
| 圆角与阴影 | 小控件、卡片、弹层分级 | 统一卡片和弹层，避免每一块都使用不同阴影 |
| 样式展示页 | 集中展示颜色、文字、卡片、按钮等 | 增加本站 `/design` 或 `/playground`，作为维护入口 |

源码中的“WCAG compliant”等注释是作者的声明，不能替代本站的对比度检查。移植颜色后，尤其要单独检查小号灰字、链接与代码注释。

### 4.2 内容与交互组件

| 组件 | 已核实能力 | 适配判断 |
| --- | --- | --- |
| 表格 | 柔和表头、斑马纹、悬停行、等宽数字、sticky 表头样式 | 高优先级；sticky 是否有效还取决于滚动容器与顶部导航偏移 |
| 手机表格 | JS 检查列数，超过 3 列的表可在窄屏变成逐行卡片 | 借鉴选项，不直接套用自动规则；论文对比表通常应保留横向布局 |
| 图片 | `figure/figcaption`、独立灯箱、前后切换、图片计数 | 高优先级；论文图需要原始比例和可读图注 |
| 代码 | 语言顶栏、复制状态、Shiki 明暗主题 | 借鉴视觉；本站先沿用 Prism，避免只为顶栏更换高亮引擎 |
| Mermaid | CSS 变量定义节点、连线、标签、背景等颜色角色 | 高优先级；让 Mermaid 与 One Dark Pro 联动 |
| 目录 | H2/H3 嵌套、编号、过滤脚注标题 | 已有目录可继续增强，不再叠加第二套目录 |
| 阅读进度 | 顶部细条按文章区域计算，而非把评论也算进正文 | 与已有返回顶部百分比共用计算源；是否再显示顶部条交给用户选择 |
| 站内文章预览 | 构建文章元数据映射，交给预览脚本显示标题、摘要等 | 中优先级；只针对站内链接做预览，适合作为“读前判断” |
| 搜索 | 独立 SearchModal 组件和结果交互 | 借鉴外观与键盘行为，保留已有中文本地索引 |
| Spoiler | 独立遮挡内容组件 | 可用于答案或推导提示，优先于复杂的新语法 |
| 分享区 | 桌面侧栏和移动端浮动操作分开 | 简化为复制链接、阅读设置即可，不照搬全部社交按钮 |

内容样式集中在 `src/styles/global.css`；响应式表格在 `src/scripts/blog-interactive.ts`；图片在 `Lightbox.astro` 和 `rehype-figure.mjs`；代码、站内预览各有独立脚本。[^niracler-prose][^niracler-interactive][^niracler-lightbox][^niracler-preview]

源码也有不宜直接照抄的部分：`rehype-figure.mjs` 遇到段落内有图片时会提取图片构造 figure，未同时保留段落中的其他文字。本站若做自动图注，转换条件应限定为“段落仅包含图片与空白”，并覆盖带链接图片、多图和图文混排的情况。[^niracler-figure]

## 5. Lowbee 与 Koharu：视觉小块和复杂交互分开学习

### 5.1 Lowbee 已公开说明的个人装修

Lowbee 的《初始之地 S2》按日期记录了实际修改；这比仅看上游主题功能列表更能判断作者做过哪些取舍。[^lowbee-custom]

| 内容 | 作者记录的实现或调整 | 本站建议 |
| --- | --- | --- |
| 封面渐隐 | `PostItemCard.astro` 使用 `mask-image` 做图片到文本的过渡 | 用于少量精选卡片；普通论文条目保留清爽文本布局 |
| 引用贴纸 | 引用块增加来源后缀和贴纸式视觉 | 可用于论文原句、核心结论；颜色使用本站 accent 的低透明度版本 |
| 图片说明 | 把图片 alt 显示在图片下方 | 设计上值得采用；实现时保留 alt 的替代文本职责，可另设 caption |
| 目录位置 | 2026-10-14 移除文章左侧标签栏并调整目录 | 与本站停用 tag 的方向一致；阅读页优先给正文和目录空间 |
| 季节归档 | 最近一年按春夏秋冬组织文章推荐 | 论文周报更适合“年份 → 月份/期号”；借鉴视觉分组，不强行季节化 |
| 更新时间 | 添加最后更新信息，曾加入“有更新”标记 | 显示更新时间即可；更新排序应有明确数据来源 |
| 首页信息区 | 最近 5 条嘟嘟、个人动态 | 可换成近期阅读/正在整理，但不应挤占论文入口 |
| 图片编排 | 连续图片根据比例组合，作者修改过判定阈值 | 论文多子图建议显式指定并排关系，不让照片比例规则决定语义 |
| 图鉴 | 每个物品一份 Markdown，用卡片展示 | 可转化为工具/项目展示页，优先级低于论文阅读体验 |

值得注意的历史变化：作者在 2026-05-06 记录更新排序和更新徽标，2026-05-08 又暂停首页按更新时间排序，并移除 MDX 依赖。这些是其项目的经历，不足以推出“Docusaurus 也应移除 MDX”。对本站更有用的经验是控制页面复杂度、避免为了小组件重做内容链路。

### 5.2 Koharu 上游的设置中心

读取的上游通过设置 registry、默认值文件和 store 管理选项。源码能力包括字体预设、字号、行高、正文宽度、两端对齐、阅读进度，以及动效强度等；部分节日和音乐选项有构建开关。[^koharu-settings][^koharu-defaults]

建议本站先提供以下精简设置，不复制全部主题控制面板：

| 设置 | 建议初始值或行为 | 原因 |
| --- | --- | --- |
| 明暗模式 | 保留当前默认暗色，允许切换浅色；可增加跟随系统 | 延续已确认偏好，兼顾访客 |
| 正文字号 | 建议提供 16、18、20px 或小范围步进 | 长文阅读中直接有用 |
| 行距 | 建议提供 1.7、1.8、1.9 三档 | 减少无意义的精细调参 |
| 正文宽度 | 标准、宽屏两档 | 宽表和图可独立突破正文宽度 |
| 纯净阅读 | 收起非必要侧栏与装饰，保留退出入口 | 对长论文笔记价值高 |
| 动效 | 默认轻量，尊重系统减少动态效果设置 | 装饰效果不应影响滚动和定位 |
| 重置 | 一键恢复站点默认 | 防止浏览者把页面调到难以阅读 |

当前中文 LXGW、英文 JetBrains 已经满足作者偏好，无需再要求访客安装字体，也不急于暴露本地字体选择器。设置保存在浏览器本地；首次渲染要尽早应用，避免进页面后字号和背景跳变。

### 5.3 Koharu 上游的代码与图表查看器

| 模块 | 源码核实到的能力 | 迁移价值 |
| --- | --- | --- |
| `CodeBlockToolbar.tsx` | 语言/标题、复制、全屏、符合条件的长代码折叠 | 高；沿用本站 CodeBlock 输出，在外层补工具栏 |
| `CodeBlockFullscreen.tsx` | 全屏代码、换行切换、复制、小屏关闭按钮 | 高；长训练脚本与配置更容易看 |
| `MermaidToolbar.tsx` | 图/源码切换、复制源码、全屏、拖动调整显示尺度 | 高；论文方法图和流程图直接受益 |
| `DiagramFullscreen.tsx` | 缩放、平移、适应窗口、键盘控制、导出入口 | 高；复杂交互可以收在查看器内部 |
| `diagram-export.ts` | 解析 CSS 变量，尝试导出 PNG，失败回退 SVG | 中；先解决可读性，再做导出 |
| `ContentEnhancer.tsx` | 单 React 根通过 portal 挂多个工具栏 | 可学习集中管理的思路，但 Docusaurus 更适合优先包裹已有组件 |

上游部分工具栏根据内容可见性挂载交互界面；这不等于整个工具栏脚本都按需下载。Mermaid 还区分等待、成功、错误和超时状态。导出逻辑特别处理了 SVG CSS 变量与 `foreignObject`，说明“加一个下载按钮”仍有跨浏览器细节。[^koharu-code][^koharu-mermaid][^koharu-diagram][^koharu-export]

本站无需把上游的 Astro 页面事件、Nanostores、Tailwind、图标系统和所有弹层整体搬入。建议使用现有 React 生命周期、CSS Modules、Docusaurus 路由与主题状态，重新实现选中的行为。

## 6. 椒盐豆豉：内容发现和小组件的持续打磨

该站以 Hugo Book 为基础做了较重修改。其“装修小记之四、五”对样式和系列功能的说明很直接；适合按需求选小功能，不能当成现成 Docusaurus 主题。[^douchi-home][^douchi-four][^douchi-five]

| 内容 | 页面或作者记录中的做法 | 本站建议 |
| --- | --- | --- |
| 系列文章 | 文章带 series 参数，文末自动列出同系列并按日期排序 | 高优先级；利用已有 collections 数据，不恢复 tag |
| 荧光笔 | 为 strong/b 添加低饱和渐变底色和圆角 | 做成可选 `<Mark>`；避免所有粗体都铺背景，尤其排除代码与公式 |
| 单篇精简目录 | 自建 compactToc 控制层级，解决目录过长 | 使用 Docusaurus 原有单页 TOC 层级参数，保留已有目录高亮 |
| 写作热力图 | 独立动态热力图页面，有专门实现教程 | 可做笔记归档页的视觉入口；内容多了再做，点击应能进入当天文章 |
| 最近更新 | 新文章和更新过的旧文都有发现入口 | 首页加一个小型“最近更新”，与论文笔记维护方式匹配 |
| 闲逛 | 随机发现文章入口 | 文章数量够多后做；只有几篇时价值有限 |
| Now 页面 | 集中呈现近况与站点变化 | 个人主页以后可加，当前不是阅读页核心 |
| Reaction | 评论系统之上增加轻量反应 | 可选；涉及后端读写，不属于纯 CSS 美化 |
| 单按钮音频 | 用紧凑播放按钮替代整条默认 audio 控件 | 有论文语音/播客内容再做，默认不要自动播放 |
| 社交与书影音 | 长毛象、NeoDB 最近内容等展示区 | 可借鉴卡片结构；本站优先展示近期阅读和研究项目 |

热力图有作者独立教程；装修文也明确区分了第三方评论系统、社交内容和模板中的系列列表。迁移时，系列导航可以只靠构建期数据；动态点赞和外部社交组件则会增加运行依赖。[^douchi-heatmap]

建议优先采用“同专题系列列表 + 可选荧光笔 + 最近更新”。不采用彩色标签云，符合当前停用 tag 的要求；货币、跑步轨迹等生活组件与论文笔记目标距离较远。

## 7. 潮流周刊：论文周报最直接的参考

潮流周刊与 Tw93 个人站是两个不同项目。前者基于 Astro，其首页封面网格、文章左侧往期列表、阅读模式和图片处理都可以找到独立源码。[^weekly-home][^weekly-repo]

| 内容 | 已核实的实现 | 本站适配 |
| --- | --- | --- |
| 周报封面卡片 | 固定 5:3 比例、标题、日期、两行摘要；封面使用 srcset | 论文周报采用期号、日期、摘要，封面可选；不强制每期找图 |
| 信息层级 | 日期独立对齐，摘要高度统一 | 列表整齐，也便于判断这一期是否相关 |
| 往期侧栏 | 由内容元数据构建链接，识别当前期，保存侧栏滚动位置 | 专题内显示周报期号；长列表按年份分组 |
| 纯净阅读 | 隐藏侧栏、部分导航、订阅和评论等，记住偏好 | 高优先级；对 MOPD 这类长文更有价值 |
| 快捷键 | 阅读模式有 R 快捷键，搜索有独立弹层 | 可借鉴；需排除输入框、可编辑区域和弹层，避免冲突 |
| 段落分享 | 选择文字后复制段落链接，打开后滚动并突出对应段落 | 中优先级；适合讨论论文中的一段解释，属于阅读交互 |
| 代码处理 | 普通代码保留横向滚动，text/markdown 类内容换行显示 | 可用于 Prompt 和长自然语言示例，不影响 Python 的缩进与行宽 |
| 搜索外观 | Pagefind 搜索界面 | 借鉴外观；本站继续使用已有中文本地搜索 |
| 图片加载 | 首图识别、尺寸元数据、CDN 转换与延迟加载分工 | 高优先级；按本站实际图源生成响应式资源，不照抄图床地址 |
| 灯箱 | PhotoSwipe 依赖与文章图片查看 | 与全站统一图片查看器合并，不让一个图触发两个插件 |
| 明暗配色 | CSS 变量统一背景、文本、分割线、强调色和搜索弹层 | 搜索、弹层也必须接入本站 One Dark Pro 变量 |

源码入口包括 `Card.astro`、`LeftSidebar.astro`、`ReaderModeToggle.astro`、`ParagraphShare.astro`、`CodeCopy.astro` 和 `rehype-image.js`。阅读模式与段落分享都是独立组件，较适合拆开参考。[^weekly-card][^weekly-sidebar][^weekly-reader][^weekly-share][^weekly-code][^weekly-image]

需要调整的部分：Astro 的页面加载事件不能原样搬到 Docusaurus；段落位置会随文章编辑变化，分享链接必须校验文本；图床 URL 参数是作者基础设施的一部分，本站应根据本地图片或自己的 CDN 制定方案。

## 8. 表格、代码块、Mermaid 的具体升级方案

这一节是面向本站的设计方案，未实施。优先复用 Docusaurus 已有输出和交互，避免同时维护多套渲染器。

### 8.1 表格：保留论文对比能力

| 层级 | 建议内容 | 实现方式 | 优先级 |
| --- | --- | --- | --- |
| 基础视觉 | 柔和表头、统一边框、合适单元格留白、克制斑马纹、行悬停 | CSS 与颜色令牌 | P0 |
| 数字可读性 | 数字列对齐、`tabular-nums`、长名称可换行 | CSS；保留 Markdown 对齐语义 | P0 |
| 宽表 | 独立横向滚动区，溢出时显示边缘渐隐和滚动提示 | Table 包裹组件 + CSS | P0 |
| 全宽/全屏 | 点击后在更宽弹层看同一张表 | React 查看器 | P1 |
| 长表 | 在指定滚动区内吸附表头，必要时固定第一列 | 选择性 CSS；校验容器关系 | P1 |
| 数据操作 | 复制为 TSV；仅显式声明的数据表提供排序 | React；保留原始文本与数据语义 | P2 |
| 手机卡片 | 只给“一个条目多项属性”的表启用 | 显式属性，不按列数全局强制转换 | P2 |

对 MOPD 这类模型/方法/指标比较表，建议默认横向滚动、可展开查看。自动拆卡片会破坏跨模型横向比较；也不应对含合并单元格、公式或复杂脚注的表默认开启排序。

### 8.2 代码块：补齐工具体验

当前安装的 Docusaurus 主题已经包含标题、行号、行高亮、复制、自动换行等能力；其中换行与复制按钮可以在本地 `node_modules/@docusaurus/theme-classic/src/theme/CodeBlock/Buttons/` 核实。官方文档也说明了代码标题、行号与高亮语法。[^docusaurus-code]

| 建议 | 具体表现 | 与现有能力的关系 |
| --- | --- | --- |
| 统一顶栏 | 左侧语言/文件名，右侧复制、换行、展开 | 优先整理现有按钮，避免重复复制按钮 |
| 全屏 | 宽代码在弹层查看，保留高亮、换行和复制 | 新增交互 |
| 长代码折叠 | 显式设置或超长时显示预览，按钮说明展开状态 | 新增交互，不默认折叠短示例 |
| Prompt 模式 | 自然语言自动换行，字号与正文协调 | 在已有换行能力上按类型配置 |
| 多版本切换 | Python、Shell、配置或前后版本用标签页 | 复用 Docusaurus Tabs，不另造 Markdown 方言 |
| 差异与重点 | 重要行、增加/删除行使用低透明度语义背景 | 扩展高亮样式，文字标记与颜色共同表达 |

One Dark Pro 的语法配色已经接入本站 Prism 主题。为实现上面的视觉与按钮，无需马上换成 Shiki；只有确实需要额外语法分析能力时再评估。

### 8.3 Mermaid：从渲染结果升级为可查看的大图

本站已开启 `markdown.mermaid` 并安装官方 `@docusaurus/theme-mermaid`。官方配置支持为明暗主题设置 Mermaid 主题与选项，适合继续包裹扩展。[^docusaurus-diagrams]

| 阶段 | 建议功能 | 实现重点 |
| --- | --- | --- |
| 基础版 | 统一图框、背景、节点、连线、标签字体与配色 | 对齐本站 token；固定像素值只放必要的尺寸变量 |
| 基础版 | 大图点击全屏 | 默认适应窗口，文字足够大；不把整个复杂图硬缩进正文 |
| 增强版 | 缩放、平移、适应窗口、恢复 100% | 正文内保留自然滚动，复杂手势放在弹层，避免抢页面滚轮 |
| 基础版 | 源码切换与复制 | 渲染失败时仍能查看和复制原始 Mermaid |
| 基础版 | 明暗切换后正确重绘 | 使用 Docusaurus 主题状态，避免旧 SVG 颜色残留 |
| 后续 | SVG/PNG 导出 | 输出中解析 CSS 变量，考虑字体、HTML 标签和跨浏览器回退 |

实现上优先包裹 `@theme/Mermaid` 或复用其客户端渲染接口；Docusaurus 本身已有错误边界，扩展时增加用户可读的错误状态与源码回退即可。不要让 Docusaurus 和另一套 Mermaid 插件同时扫描同一代码块。

## 9. 图片、提示块与其他排版细节

| 内容 | 推荐表现 | 适配方式 |
| --- | --- | --- |
| 单张论文图 | 保留原比例；正文预览清晰；点击查看原尺寸 | 现有图片缩放能力评估后统一增强 |
| 图注 | 图下小号说明，图与说明作为整体 | 编译期 figure 转换，或 MDX Figure 组件 |
| 多图 | 双列/三列，窄屏顺序堆叠；同一组可连续查看 | 显式 FigureGroup，避免按文件名或比例猜测语义 |
| 透明图/SVG | 受控的中性底色，不全局反相 | 主题变量与可选图片属性 |
| 加载 | 提前保留尺寸，正文以下延迟加载，失败有替代文本 | 编译期元数据 + 浏览器加载属性 |
| 提示块 | 核心结论、实现细节、局限分别使用有限语义类型 | 美化 Docusaurus 原有 admonitions |
| 折叠块 | 推导细节、补充实验可展开，标题明显 | 原有 details/MDX 组件，统一箭头和边框 |
| 正文强调 | 只对关键短语使用低饱和底色 | 可选 Mark，排除代码、公式和长段落 |
| 站内预览 | 悬停/聚焦显示标题摘要，小屏点击采用明确行为 | 使用已有内容目录数据，按需加载 |
| 脚注外观 | 统一上标、回跳按钮、目标高亮；浮窗以后再做 | 先补样式，不引入文献管理系统 |

现有 `plugin-image-zoom` 基于 medium-zoom，已经覆盖基础点击放大。若目标只是论文图放大，先完善现有能力即可；若明确需要图集切换、手势与原图查看，再评估用 PhotoSwipe 替换。PhotoSwipe 官方提供独立 lightbox 接入方式，Tw93 两个项目也提供了对应参考。[^photoswipe]

当前配置还有一个应补齐的基础项：数学插件只在 blog 配置，docs 尚未同样配置；KaTeX CSS 引用为 0.13.24，而锁定依赖中的 KaTeX 为 0.16.47。实施论文阅读页时应统一 docs/blog 数学链路与样式版本。这是页面正确性的准备工作，不扩大为文献系统改造。

## 10. 在当前仓库中的实现分工

| 工作 | 建议位置/方式 | 原因 |
| --- | --- | --- |
| 颜色、阴影、边框 | 继续扩展 `src/css/palette.css`、`src/css/theme.css` | 已有集中管理入口 |
| 字号、行高、间距、正文宽度 | 单独建立 typography/layout token 层 | 避免所有调整挤入全局 custom.css |
| 排版展示页 | `src/pages/design.tsx` 或 `src/pages/playground.tsx` | 固定验收入口；名称为拟议 |
| 代码/表格/Mermaid | 定向包裹 Docusaurus 主题组件；需要时 swizzle 局部 | 保留原始渲染、路由、主题能力，减少维护副本 |
| 图注与元数据 | 小型 remark/rehype 转换 | 适合构建时决定的结构，不在客户端扫描全文重排 |
| 读者设置 | 小型 React 面板 + 本地持久化 + 早期应用偏好 | 一处管理字号、行距、纯净模式 |
| 系列与周报 | 复用 `plugins/content-catalog` 与 collections | 已有 Agent、论文周报数据，无需 tag |
| 搜索 | 美化现有 easyops 本地搜索 | 保留已建立的中英索引能力 |

采用插件的条件是它确实提供一项缺少的基础能力。图注的结构转换适合 remark/rehype；灯箱可使用成熟库；工具栏、阅读面板、卡片和配色则主要靠 React 与 CSS。不能期待安装一个“美化插件”就统一字体、留白、表格和移动端。

从 Astro 移植时必须替换 `Astro.props`、页面事件与内容查询；从 Jekyll/Hugo 移植时必须替换模板与 shortcode。CSS 也要把上游 token 映射为本站语义变量。移植单位建议是一项完整行为，例如“代码全屏”，而不是整个主题目录。

## 11. 推荐的实施顺序

### 11.1 排序依据

优先级按四个因素判断：对理解论文内容的帮助、能覆盖多少页面、当前内容是否已经需要、实现后需要维护多少额外代码。不用主观百分比分数制造精度；下表是面向当前站点的判断，不是通用博客功能排名。

当前 MOPD 笔记的 Markdown 源码有 72 个标题、4 张表，尚无 Markdown 图片、围栏代码或 Mermaid。这解释了为什么宽表和长文定位应先于复杂代码、图表工具。后续开始大量加入图片、代码或 Mermaid 时，对应项目可以提前；这些数量只描述当前这篇文件，不代表未来的内容比例。

P0 是第一轮应完成的部分，P1 是随后按内容需求推进的增强，P2 是后续可选项。S/M/L 表示相对工程量，不是固定工时。第 1 项包含排版实验页作为验收工具；只建实验页而不改善真实文章，不算完成。

### 11.2 按重要性排序

| 排名 | 项目 | 为什么排在这里 | 第一版范围 | 优先级 / 复杂度 |
| --- | --- | --- | --- | --- |
| 1 | 正文排版与主题一致性 | 覆盖所有文章，也是最直接的视觉变化 | 标题、正文、元信息、列宽、块间距、明暗颜色；配一张排版实验页 | P0 / M |
| 2 | 表格阅读体验 | 现有论文笔记已有比较表，直接影响信息理解 | 表头、留白、数字对齐、横向滚动、溢出提示；宽表展开查看 | P0 / M |
| 3 | 长文定位与纯净阅读 | 72 个标题需要有效定位；已有进度状态可以复用 | 收敛目录层级、手机当前章节入口、打开目录定位当前项、纯净阅读开关 | P0 / M |
| 4 | 论文图片与图注 | 开始加入方法图、实验图后收益很高，但当前样例尚无图片 | 图注、保留比例、原图放大、尺寸占位；图组按需加入 | P1 / M |
| 5 | 代码块统一工具栏 | 训练脚本与配置会受益，基础复制和换行已经存在 | 语言/文件名顶栏、整理现有按钮、全屏；长代码折叠按需启用 | P1 / M |
| 6 | Mermaid 大图查看 | 对方法流程说明有用；先覆盖基本查看，再处理复杂导出 | 主题联动、全屏、适应窗口、源码/图切换；之后加平移缩放 | P1 / M–L |
| 7 | 专题、周报与首页入口 | 帮助访客找到内容；已有专题和文章卡片可继续打磨 | 期号、摘要层级、年份分组、当前项、同专题文章导航；封面可选 | P1 / S–M |
| 8 | 提示块、引用、折叠与强调 | 增加内容层次；视觉部分成本低，可随第 1 项一并完成 | 有限语义类型、引用来源、折叠标题、可选荧光笔；不全局改造粗体 | P1 / S |
| 9 | 搜索弹层美化 | 搜索已有功能基础；文章数量增加后价值上升 | 结果标题、路径、摘要、选中态、键盘提示与空结果样式 | P1 / S–M |
| 10 | 站内预览与段落分享 | 有用，但不解决当前最主要的排版和阅读问题 | 先站内文章预览，再做选择文字后的段落链接 | P2 / M |

这个表按价值排序，施工时可以合并低成本工作。例如第 8 项的颜色和间距样式适合随第 1 项完成；第 5、6 项的弹层应共用基础组件。完整的阅读设置面板在纯净模式之后做，先提供字号、宽度与恢复默认，暂不增加任意字体和大量滑块。

### 11.3 各项具体参考与迁移判断

1. **正文排版：参考 Niracler 的 `tokens.css`、`DESIGN.md` 与设计展示页，以及 Tw93 的正文布局变量。** 学它们如何规定页面、卡片、正文、说明文字与留白。本站保留 LXGW、JetBrains 和 One Dark Pro，补上字号、间距、圆角与宽度变量，不重新做一套视觉身份。验收时以真实文章为主，实验页用于回归比较。[^niracler-design][^niracler-tokens][^tw93-tokens]
2. **表格：参考 Niracler 的 `global.css` 和 `blog-interactive.ts`。** 学表头、斑马纹、数值排版和响应式容器。其超过 3 列转手机卡片的规则不适合直接套用论文比较表；本站保留横向对比关系。滚动区要能通过键盘操作，并在需要时提供可理解的名称，不能只显示一条难发现的滚动条。[^niracler-prose][^niracler-interactive][^mdn-overflow]
3. **长文导航：新增参考 Koharu 的 `MobilePostHeader` 和 `MobileTOCDropdown`，纯净阅读参考潮流周刊。** 上游把当前章节与可展开目录整合在手机页头，并在打开目录时定位当前项。本站保留已有分节进度，借用入口和定位行为；无需为进度环引入完整动画依赖，也不再新增第三种阅读进度显示。纯净模式必须始终有退出入口。[^koharu-mobile-toc][^weekly-reader]
4. **图片：参考 Tw93 的 PhotoSwipe 接入、Lowbee 的图注与潮流周刊的图片处理。** 第一版先完善现有 medium-zoom，加入图注和尺寸占位；需要图组前后切换时再换查看器。PhotoSwipe 的缩放、错误提示与配置可读官方文档；它不自带图注，图注要通过 API 或插件另接，而且页面内仍应有可读说明。[^tw93-js][^lowbee-custom][^weekly-image][^photoswipe-options][^photoswipe-caption]
5. **代码：参考 Koharu 的工具栏与全屏，再补看 Expressive Code 的 Editor & Terminal Frames 和 Word Wrap。** 新参考展示了按代码类型区分框架、文件名标题、复制入口，以及换行后保留缩进的方式。本站学习交互和视觉，先沿用 Docusaurus/Prism；不是看到新库就替换现有渲染器。[^koharu-code][^expressive-frames][^expressive-wrap][^docusaurus-code]
6. **Mermaid：参考 Koharu 的图表弹层、Niracler 的颜色角色，并补查 Mermaid 官方主题配置。** 官方可定制的主题为 `base`，`themeVariables` 的颜色要求用十六进制值；不能想当然把 `var(--site-accent)` 直接当颜色传入推导引擎。实施时将当前主题变量解析为实际颜色，或维护与站点 token 同源的配置；切换主题后检查重绘。导出放后面。[^koharu-mermaid][^koharu-diagram][^niracler-tokens][^mermaid-theme]
7. **专题和首页：参考潮流周刊 `Card.astro`、`LeftSidebar.astro` 与椒盐豆豉的系列列表。** 首页继续展示 Agent 和论文周报；周报使用期号、日期、摘要，封面只是可选增强。专题页与文章内系列导航复用现有内容目录。专题归属不自动等于阅读顺序；有明确先后关系时，应另设顺序字段或确认排序约定。[^weekly-card][^weekly-sidebar][^douchi-five]
8. **提示块：参考 Lowbee 引用样式、椒盐豆豉荧光笔，再使用 Docusaurus 原生 admonitions 作为结构。** 原生提示块支持定制渲染，简单美化可以只改 CSS；常见 note、tip、warning 不需要另一套解析插件。代码和公式排除荧光笔样式。[^lowbee-custom][^douchi-four][^docusaurus-admonitions]
9. **搜索：参考 Tw93 的搜索弹层和 Niracler 的 SearchModal。** 美化已有 easyops 本地搜索，重点是结果的信息层级、键盘可操作性和明暗一致性。换 Pagefind 或接远程搜索不属于这一轮视觉需求。[^tw93-search][^niracler-repo]
10. **站内预览和段落分享：参考 Niracler 的预览元数据与潮流周刊 `ParagraphShare.astro`。** 优先从现有内容目录拿标题和摘要；段落分享必须校验文本，不能只记一个会随编辑变化的段落序号。[^niracler-preview][^weekly-share]

### 11.4 实现路线与批次

Docusaurus 官方将主题定制区分为 wrapper 和 eject：前者包裹原组件，后者复制原实现。为减少升级时要维护的内部代码，默认先用 CSS 与 wrapper；原组件结构无法满足需求时再局部替换，并核对该组件的定制稳定性。不能把“使用 wrapper”理解为所有内部接口都稳定。[^docusaurus-swizzling]

| 批次 | 交付内容 | 可直接观察的结果 |
| --- | --- | --- |
| 第一批 | 排版与设计变量、基础提示块、表格、长文目录与纯净模式 | 当前 MOPD 页面就能看到正文层次、表格可读性、长文定位的改善 |
| 第二批 | 图片与代码、Mermaid 的查看器；补充真实使用示例 | 图片和代码可清晰展开，大图可查看，组件沿用同一套主题 |
| 第三批 | 周报/专题浏览、搜索外观、精简阅读设置 | 内容发现和个人阅读偏好更顺手 |
| 第四批 | 站内预览、段落分享、按需的图表导出 | 在已有阅读体验稳定之后补充操作便利性 |

图片、代码与 Mermaid 应先确认首批文章的实际使用方式，再确定默认按钮和折叠规则。无需为了填满组件演示而向论文笔记插入无关图片或流程图。

全局背景视频、粒子、音乐自动播放、复杂鼠标跟随不进入推荐批次。热力图、随机文章、近期动态保留为以后可选项；它们对当前论文阅读的帮助低于前面的内容组件。

建议用现有 MOPD 长文、一篇短博客和独立组件实验页验收：320/375px 手机、768px 平板、1440px 桌面；明暗主题；长中英标题；超宽表；长代码；Mermaid 大图；无图文章。交互需要检查 Esc 关闭、焦点返回、键盘滚动、路由切换后事件清理、减少动态效果，以及图片加载后目录和阅读进度是否更新。没有真实使用内容的组件先在实验页验证，不声称已经在全部文章中实测。

## 12. 当前状态与交付范围

仓库已经有目录高亮与分节进度、返回顶部百分比、文章与论文卡片、Agent/论文周报专题、集中配色、本地字体、本地搜索和基础图片放大。这些应作为后续增强的基础，不重复安装相同功能。

这一轮只更新调研文档，没有迁移上述新组件，没有更改现有页面、依赖、标签开关或部署。源码快照用于调研分析，实际实施时需要重新核对所选文件与依赖版本。
